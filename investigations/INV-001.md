# INV-001: SSH login attempts as a non-existent user

## Alert

Rule 5710, "sshd: Attempt to login using a non-existent user", level 5, agent wazuh-server (000).
9 alerts on 21 Sep 2026, around 10:27 UTC (15:57 IST).

## Evidence

- journalctl on the VM showed "Invalid user wronguser" and "Failed password for invalid user wronguser" from 10.0.2.2
- wazuh-logtest, tested manually with the same log line, matched rule 5710 and said "Alert to be generated"
- Discover (wazuh-alerts-*) showed 9 hits for rule.id:5710 in the matching time window

## Timeline (UTC)

- 10:27:05 first failed login attempt

## Analysis

I ran two SSH connections from my own laptop to the VM, using a username, wronguser, that does not exist on the system. Every attempt came from 10.0.2.2, which is how the laptop appears to the VM through VirtualBox's NAT network. Wazuh's default rules correctly identified this as a non-existent-user login attempt.

## Verdict

True positive. Cause: my own authorised test. Confidence: high, because I made every attempt myself and know the exact time and source.

## What would change my mind

A source address other than 10.0.2.2 appearing in the same alert pattern, or login attempts I did not personally make.

## Detection gap

The first run of this test produced 0 alerts, even though the endpoint log clearly showed the failed logins. wazuh-logtest confirmed the rule itself works correctly on that exact log line, so the rule was not the problem. After restarting wazuh-manager, the same test produced 9 alerts immediately. My best explanation, not proven, is that the log-reading process silently stalled after an earlier VM freeze (a 37-minute soft lockup) and only recovered once the manager was restarted.

## Lesson learned

After any VM freeze, crash, or reboot, restart wazuh-manager and re-run a test before trusting that the SIEM is working. A silent detection gap like this would be dangerous in a real environment.
