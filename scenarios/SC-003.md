# SC-003: Scheduled Task Creation

## Objective

Create and delete a harmless scheduled task in the authorized lab,
then check whether Sysmon and Windows Security auditing capture the activity.

## ATT&CK Technique

T1053.005 — Scheduled Task/Job: Scheduled Task

## Prerequisites

- Windows lab endpoint `win-client`
- Active Wazuh agent
- Working Sysmon collection, verified in INV-002 and INV-003
- An elevated PowerShell session

## Test Procedure

Use `schtasks.exe` to create a test task that calls `whoami.exe`.
Confirm successful creation, then delete the task.

## Original Prediction

- Sysmon Event ID 1 would record `schtasks.exe` process creation.
- Windows Security Event ID 4698 would record task creation if the
  required auditing was enabled.

The original scenario incorrectly assumed that Sysmon process-create
telemetry would always be present. Collection depends on the active
Sysmon configuration.

## Observed Outcome

- Task creation and deletion returned success.
- No matching `schtasks.exe` event was found in the searched Sysmon log.
- No corresponding Sysmon result was found in Wazuh.
- Windows Security Event 4698 was initially absent.

After enabling successful auditing for **Other Object Access Events**
and repeating task creation:

- Windows Security Event 4698 was collected.
- Wazuh default rule **60228**, level **4**, covered the event.
- The observed rule mapped to parent technique **T1053**, not T1053.005.
- An initially added custom rule was removed because it duplicated
  existing coverage.

## Remaining Limitation

The original Sysmon visibility gap remains. Detection was restored
through a second telemetry source, not by changing the Sysmon configuration.

These results apply to the tested lab configuration, not every
scheduled-task creation method or environment.

## Cleanup and Safety

- Delete the test task and confirm its removal.
- Use only an authorized, disposable lab endpoint.
- Do not create tasks on production or third-party systems.
